## 目標

楓之谷的投票結算時，除了原本的結果報表，再自動貼一份**出團名單**：取**前兩高票**的日期，
各自把出席的人依職業編成一隊、二隊、候補，格式像這樣：

```
9/3 (四) 晚上九點
一隊
173箭神（樸）
166夜使者（肥熊）
164冰雷（ㄧㄅ）
160火毒（毛）
157黑騎士（悠悠）
153聖騎士（cy）

二隊
169黑騎士（史加納）
168刀賊（daychuan）
164神射手（Vcore）
157英雄（阿丞）
150拳霸（阿水）
143刀賊（john）
```

用途是**方便統計與複製**，不是權限控管。

## 資料從哪來

**職業已經在投票資料裡了**，不需要另外維護：

```js
tally(poll).options[i].entries   // → [{userId, options, identity}, ...]
```

每個選項（＝一個日期）底下就是「誰投了這天、他用哪個職業」。所以：

| 要什麼 | 從哪來 |
|---|---|
| 日期、星期 | 選項的 `label`（模板產生的日期字串） |
| 誰出席 | 該選項的 `entries` |
| 職業 | `entry.identity`，用 `identityLabel()` 轉成正式名稱 |
| **等級、角色名** | **← 只有這兩項要新的 JSON 表** |

---

## 人員表的 key 是「Discord ID ＋ 職業」，不是 Discord ID

投票支援一人多角色（`multi_char`），同一個人可以登記刀賊 168 和冰雷 150 兩隻，
**等級是角色的屬性不是人的屬性**。用 Discord ID 當唯一 key 存不下第二隻。

```
data/roster.json（不進版控）
{
  "version": 1,
  "updatedAt": "...",
  "members": {
    "<discordId>:<identity>": {"level": 168, "name": "daychuan", "updatedAt": "..."}
  }
}
```

外層包一層 `version` / `members`，理由與 `selfRoles.json` 相同：格式判斷與日後 migrate 需要一個版本號，扁平 map 沒有地方放。

同一隻角色由多人共用時（例如三個人輪流開拳霸「短拳」），就**每個 Discord ID 各存一筆**、內容相同，
這樣不管誰投那個職業都查得到等級與角色名。

`identity` 存**職業表的 value**（例如 `shadower`）而不是中文標籤——標籤日後可能改字，value 不會。

**查不到的人不能被丟掉**：等級顯示 `??`、角色名退回 Discord 的顯示名稱，照樣排進隊伍。
名單少一個人比顯示 `??` 嚴重得多。

## 分隊規則（2026-09-03 使用者確認）

**一隊固定這六個職業，順序就是輸出順序：**

```
箭神、夜使者、冰雷、火毒、黑騎士、聖騎士
```

| 情況 | 規則 |
|---|---|
| 一隊某個職業沒人 | 該行顯示 `(缺人)` |
| **冰雷**有多人 | **等級最高**的進一隊 |
| **黑騎士**有多人 | **等級最低**的進一隊 |
| 其餘四個固定職業有多人 | 一隊取一個（等級最高），其餘進二隊 |
| 不在固定六職裡的職業 | 全部進二隊 |
| 二隊 | 上限 6 人，依等級由高到低 |
| 第 13 人起 | 進「候補」，一樣依等級由高到低。**候補不設上限**，全部列出 |

> 冰雷取高、黑騎取低是刻意不對稱的，不是筆誤。實作時**不要「順手統一」**。

## 要出幾份名單（2026-09-03 修訂）

從最高票的層級往下取，**湊到兩天就停**。同一層級（同票數）的日期一定整組列出，不會只列其中一個。

| 票數 | 出幾份 | 為什麼 |
|---|---|---|
| 5、5、3、1 | **兩份**（9/3、9/4） | 最高票就有兩天，夠了，**不再取第二高票** |
| 5、3、3、1 | 三份 | 最高票只有一天，往下取 3 票那層，平手兩天全列 |
| 5、3、1 | 兩份 | 一份加一份 |
| 4、4、4、2 | 三份 | 最高票三天並列，全列，一樣不往下取 |

另有 `TOP_OPTION_LEVELS = 2` 當保險：最多往下取兩個票數層級，避免「5、1、1、1、1」一路撈到底。

## `/roster` 的權限（2026-09-03 使用者確認）

| 子指令 | 誰能用 | 做什麼 |
|---|---|---|
| `/roster list` | 所有人 | 一般成員只看到**自己的**角色；管理員看到全部 |
| `/roster level <職業> <等級>` | 所有人 | 只改**自己已登記**角色的等級 |
| `/roster edit <user> <職業> <等級>` | 管理員 | 改**別人**已登記角色的等級（角色名不動） |
| `/roster set <user> <職業> <等級> <角色名>` | 管理員 | 新增或整筆覆寫 |
| `/roster remove <user> <職業>` | 管理員 | 刪除 |

一般成員**不能新增、不能改角色名、不能碰別人的資料**。
`level` 與 `edit` 都只改**已經存在**的那一筆，查不到就不動作 ——
順手建一筆的話，職業選錯就會多出一筆永遠對不到投票的孤兒資料，而且本人看不出來。

`edit` 與 `set` 的分工：`edit` 只動等級，是「幫大家更新等級」的日常操作；
`set` 整筆覆寫（角色名是必填），用來新增或改名。日常維護用 `edit` 才不會不小心把角色名洗掉。

**職業的下拉選單列的是全部 12 個職業，沒辦法只列出你自己有的那幾隻。**
那需要 autocomplete，而 `src/events/interactionCreate/` 目前沒有 `isAutocomplete()` 的分派
（`src/commands/vmute/index.js` 有註解說明這個專案刻意不用它），改它超出 U11 的檔案領域。
折衷做法：選到自己沒有的職業時，回覆裡直接把他名下有哪幾隻列出來。

## 驗收

**單元測試**（`lineup.js` 不得碰 discord.js，職業一律用 value 傳入）：

1. 六個固定職業各一人 → 一隊剛好六人，**順序是箭神、夜使者、冰雷、火毒、黑騎士、聖騎士**
2. 缺某個固定職業 → 該行是 `(缺人)`，其他人位置不跑掉
3. **兩個冰雷 → 等級高的在一隊**，低的在二隊
4. **兩個黑騎士 → 等級低的在一隊**，高的在二隊
5. 三個火毒 → 一隊一個（最高），另外兩個進二隊
6. 不在固定六職的職業（英雄、拳霸…）全部進二隊
7. 13 人以上 → 第 13 人起進候補
8. 人員表查不到的人 → 等級顯示 `??`，**人不會消失**
9. 票數 5、5、3、1 → 只產生**兩份**名單（最高票就有兩天，不取 3 票那天）；
   5、3、3 → 三份；5、3、1 → 兩份；4、4、4、2 → 三份

**實機（測試伺服器）：**

10. 管理員 `/roster set` 建立幾筆、`/roster list` 看得到全部；
    一般成員 `/roster list` 只看到自己的、`/roster level` 改得動自己的等級、
    `/roster set`、`/roster edit` 與 `/roster remove` 被擋下來；
    管理員 `/roster edit` 改得動別人的等級，而且角色名沒被洗掉；
    改到對方沒登記的職業時，回覆會列出他實際有哪幾隻
15. **新增 `/roster` 之後必須跑 `yarn deploy`**，只重啟 bot 的話 Discord 看不到這個指令
11. 楓之谷投票結算 → 結果報表之後**多貼一則名單**，格式與等級正確
12. 非楓之谷的投票結算 → **不產生名單，也不報錯**
13. 有人沒登記在人員表 → 顯示 `??` 但仍在名單上
14. U10 上線後：開在討論串的投票結算 → 名單也貼在討論串裡
