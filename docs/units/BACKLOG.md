# 待辦（尚未成為單元）

想法先記在這裡，真的要做時才寫成 `UXX-*.md`。
每一項都要有「為什麼」與「已知的坑」，否則之後看不懂當初在想什麼。

---

## B1　投票討論串滿 30 天自動刪除

**why**：測試 25 分鐘就開了 4 個討論串；每週投票長期跑下來，頻道側邊會塞滿沒人看的舊串。

**怎麼做**：`pollArchive.purgeExpired()` 已經在每次開機跑（清 90 天前的歷史投票），
歸檔紀錄裡就有 `channelId`（開串的話那就是討論串 id），在那裡多一步即可。

**判斷條件用「結算後滿 30 天」，不要用「最後活動時間」**——討論串是鎖定的，
沒人能發言，活動時間永遠停在 bot 發訊息那一刻，拿它判斷等於沒判斷。

**⚠️ 一定要守的安全條件**：刪之前必須 `channel.isThread()` 確認。
沒開串的投票，`channelId` 是**正式的文字頻道**，少這一行就是把頻道刪掉，救不回來。

規模：約 40 行 ＋ 測試。需要 `ManageThreads` 權限。

## B2　支援「不帶日期」的選項（例如「無法參與」）

**why**：使用者想在帶日期的模板裡加一個「無法參與」。

**現況是不能加，會把所有日期算錯。** `pollTemplate.js` 的 `dayOffsets()`：

```js
const weekdays = bases.map((base) => weekdayOf(base))
if(weekdays.some((day) => day === null)) return bases.map((_, index) => index)
```

**只要有任何一個選項解析不出星期幾，整份清單就退回「第 N 個選項＝起始日 +N 天」**。
「星期一、星期三、星期五」加一個「無法參與」之後會變成 9/1、9/2、9/3——
星期三與星期五的日期直接錯掉，而且畫面上看起來像是正常的日期，不會有人發現。

**要做的話**：需要一個「這個選項不參與日期計算」的標記（例如以 `-` 開頭）。
影響範圍：`dayOffsets`、`applyDates`、`optionDateRange`、U11 的分隊
（「無法參與」不能拿去編隊）、以及「最高票」判定（它可能變成最高票）。

規模：中。**在做之前請勿在模板裡加這類選項。**

## B3　截止前提醒尚未投票的人

**why**：投票常常拖到最後才有人投，甚至忘記。

**材料都在**：投過的是 `Object.keys(poll.votes)`；該提醒誰是 `noticeRoles.poll`
那個身分組的成員（U10 已經加了這個設定）；兩者相減就是未投票名單。
排程用現成的 `scheduleAt(closeAt - N 小時)`。

**要先決定**：提前幾小時、提醒幾次、以及「一場投票只提醒一次」怎麼記
（重啟還原時不能重複發，要有旗標寫進投票紀錄）。

規模：小到中。

---

## B4　最高票日期的集合提醒文字

**why**：使用者想在指定頻道發一段像這樣的提醒：

```
［提醒］9/3 晚上八點五十分 於「生命之穴入口」處集合，
到時候回響會叫在外面，請不要急著變身進場。
```

**狀態：使用者 2026-09-03 明確表示先不做**，因為要輸入的參數太多
（集合時間、集合地點、注意事項、發到哪個頻道，而且可能每場不同）。

真的要做時，第一件事是決定這些參數放模板還是放 `/poll` 的參數——
放 `/poll` 會讓參數列爆掉（目前已經 15 個），放模板則 Modal 只剩不到欄位可用
（`TEMPLATE_MODAL_FIELDS` 已滿 5 個，見 U10 的說明）。
