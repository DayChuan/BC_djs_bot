## ⚠️ 開工前必須先確認的四件事

這個單元**現在還不能動手**，四個問題沒答案就會寫出白工。

### 1. Discord 那邊，先確認能不能用「追蹤頻道」解決

Discord 內建一個功能叫 **追蹤（Follow）**：
如果對方的公告頻道是**公告頻道（Announcement Channel）**類型，
你可以在自己的伺服器裡點「追蹤」，之後對方發的每一則公告都會**自動轉發到你指定的頻道**。

**零程式碼、零維護、不需要 bot。**

所以第一件事不是寫程式，是去看：

1. 楓之谷官方 Discord 的公告頻道，標題旁邊有沒有「📢」或「追蹤」按鈕
2. 有的話直接追蹤，看轉發過來的內容夠不夠用

**如果夠用，這個單元的 Discord 部分就不用做了。**
不夠用（例如你只想要特定類型、或想整理成討論串）才需要寫程式。

> 真要用 bot 讀對方伺服器的訊息，前提是 **bot 必須被邀請進那個伺服器**。
> 官方伺服器通常不會讓外部 bot 進去，所以這條路多半走不通——**先確認追蹤功能**。

### 2. 官網那邊，先找有沒有 RSS

有 RSS 的話，整個單元就是 U14 換一個網址加一組設定，**工作量差十倍**。

怎麼找：
- 公告頁原始碼裡搜 `rss`、`feed`、`atom`
- 試 `<官網網址>/rss`、`/feed`、`/news/rss` 這類常見路徑

**沒有 RSS 就得爬 HTML**，而爬 HTML 的東西會因為對方改版而壞掉，
且壞掉時通常是安靜的（抓到空字串）。這是完全不同等級的維護成本，要先知道。

### 3. 「重要內容」的定義

楓之谷的公告量很大——改版、活動、維護、商城、處分名單。
**全部搬過來等於換一個地方洗版。**

要先定義哪些要搬，例如：
- 只要標題含「改版」「更新」的
- 只要某個分類（如果官網有分類）

### 4. 網址與頻道

- 官網公告頁的**確切網址**
- 要發到哪兩個頻道（通知頻道、內容頻道），測試站與正式站各一組

## 做法（等上面四項確認後才定案）

**預期是 U14 的延伸，不是另寫一套。**

U14 做完之後會有一條完整的管線：

```
來源 → items（title / link / 時間 / 內容）→ 關鍵字過濾 → 扣掉看過的
     → 開討論串搬內容 → 通知頻道貼短訊 → 記住 guid
```

**中間到最後那一整段，楓之谷完全一樣。** 不同的只有最前面「怎麼拿到 items」：

| | Minecraft（U14） | 楓之谷（U15） |
|---|---|---|
| 來源 | RSS | RSS（若有）或爬 HTML |
| 解析 | `fast-xml-parser` | 同左，或自己抽 HTML |
| 之後的步驟 | — | **完全共用** |

所以 U15 的第一步是**把 U14 的後半段抽成共用模組**（例如 `src/core/newsPipeline.js`），
U14 與 U15 各自只提供一個「來源轉換器」。

> **刻意不要在 U14 就先抽象化。** 只有一個來源時抽出來的介面，第二個來源一定不合用。
> 等 U15 真的知道楓之谷的來源長什麼樣，再回頭抽——那時候才知道兩者的共同點在哪。
