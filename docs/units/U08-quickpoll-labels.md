# U08　`/quickpoll` 自訂選項文字 ＋ 藍紅順序對調

狀態：待驗收
進度：3/4
依賴：無
可平行：可
分支：直接在 `test` 上（改動只有兩個檔、三十行）
來源：使用者 2026-08-21 的功能修正

---

## 目標

兩件事：

1. `/quickpoll` 選好幾選一之後，可以自己指定每個選項的文字（例：藍＝會中、紅＝想太多）。原本只能是「紅」「藍」「灰」「綠」四個字
2. **藍排到紅前面**。藍是預設的正向選項，發起人不必每次都在題目裡補一句「藍是贊成」

## 為什麼直接做掉

改動集中在兩個檔、不新增模組、不動資料格式，開一條分支再合併的成本比改動本身還高。與 U01～U06 的檔案領域也沒有重疊。

---

## 改了什麼

**`src/core/pollRender.js`**

- `QUICK_COLORS` 的順序由 `紅藍灰綠` 改為 **`藍紅灰綠`**。key 仍是 `o0`～`o3`，所以 `o0` 現在是藍色
- `styleOf()` 由「用 key 查」改為「**先比對文字、再退回用 key 查**」

**`src/commands/quickpoll/index.js`**

- 新增選填參數 `labels`：依「藍,紅,灰,綠」的順序用逗號分開。不給就沿用顏色名，跟改版前一樣
- 解析直接用 `pollStore.parseOptionsInput()`（已有單元測試）：吃全形逗號、去空白、去重複、回傳的 key 依序就是 `o0`、`o1`…，剛好對上顏色順序
- 數量對不上就**擋下來並說明**，不補預設也不截斷
- `choices` 的說明文字與三個選項名改為藍在前
- 啟動 log 多印一組實際的選項文字

### 兩個設計取捨

**為什麼 `styleOf()` 要多一段用文字比對**：2026-08-21 之前發出的快速投票，資料裡的 `o0` 標的是「紅」。只用 key 查的話，那些訊息重畫時會變成「紅」字配藍底。舊投票最多再活 24 小時（`minutes` 上限），但顏色對不上的按鈕在語音現場就是會被按錯。自訂文字不會撞到「藍」「紅」「灰」「綠」這四個字，所以退回 key 那條路徑照樣正確。

**為什麼數量不符是拒絕而不是自動補齊**：按鈕文字與顏色一旦錯位，現場就是集體投錯，而且沒有人會發現。寧可讓發起人重打一次。

## 驗收

沒有新的單元測試：解析走的是 `parseOptionsInput()`，`tests/pollStore.test.js` 已經涵蓋；其餘都是按鈕排列與文字，依 `docs/units/done.md` 的 D09 決議不寫介面測試。

實機（測試伺服器）：

1. `/quickpoll question:要開團嗎 choices:2` → 按鈕依序是**藍「藍」、紅「紅」**
2. `/quickpoll question:要開團嗎 choices:2 labels:會中,想太多` → 藍底顯示「會中」、紅底顯示「想太多」
3. 同上但 `labels:會中` → 被擋下並提示要剛好 2 個，**沒有發出投票**
4. `choices:4 labels:甲，乙，丙，丁`（全形逗號）→ 四顆按鈕依序是藍甲、紅乙、灰丙、綠丁
5. 投票、取消（再按一次同一顆）、到時間自動結束、按「結束投票」提早結算，全部照舊
6. 部署前發起的舊投票若還開著 → 按鈕顏色與文字仍然對得上（藍＝藍、紅＝紅）

## 決策紀錄

- 2026-08-21　藍排最前面，作為預設的正向選項。使用者指定。
- 2026-08-21　自訂文字用單一 `labels` 參數逗號分隔，不做四個獨立參數。理由：與 `/poll` 的 `options` 同一種寫法，指令列也不會被四個選填參數塞滿。
- 2026-08-21　數量不符一律拒絕，不自動補齊或截斷。
