# U08　投票選項的日期改為依星期對齊

## 來源

2026-08-27 使用者於對話中回報的 bug（非 Handover 文件）。

## 問題

模板 MapleStory 的選項是：

```
星期二,星期三,星期四,星期五,星期六早上,星期六下午,星期六晚上,
星期日早上,星期日下午,星期日晚上,星期一
```

套用日期時，`applyDates()` 是用**索引**遞增（第 n 個選項 = 起日 + n 天），
於是「星期六早上／下午／晚上」變成連續三天：

```
星期六早上(9/6)  星期六下午(9/7)  星期六晚上(9/8)   ← 錯，應該都是同一天
```

## 決策紀錄

### 為什麼不寫死索引 5~7、8~10

使用者提的方案之一。不採用：正確性會綁在「這個模板剛好 11 個選項、順序不變」上。
之後只要加一個「星期五晚上」，索引整個位移，日期又錯，而且不會有任何錯誤訊息。

### 為什麼不改成「全部由程式運算、不存選項」

使用者提的方案之二。不採用兩個理由：

1. 會把「週末拆早上／下午／晚上」這條楓之谷專屬規則寫進核心，
   其他模板（TRPG、臨時投票）就用不了日期功能。
2. 不存選項的話，`/poll_admin` 就沒有東西可以改 —— 與使用者同時提出的
   「管理員要能臨時修正選項」需求直接衝突。

### 採用：日期由選項文字裡的「星期X」推算

```
起日 2026-08-18（星期二）

星期二      → (2-2+7)%7 = 0 → 8/18
星期六早上  → (6-2+7)%7 = 4 → 8/22 ┐
星期六下午  → 4              → 8/22 ├ 同一天
星期六晚上  → 4              → 8/22 ┘
星期一      → (1-2+7)%7 = 6 → 8/24
```

三條規則：

1. 抓選項開頭的星期（`星期X` / `週X` / `周X` / `禮拜X`，`日` 與 `天` 都算星期日），
   日期 = 起日 + `(目標星期 - 起日星期 + 7) % 7` 天
2. **只要有一個選項認不出星期，整組退回原本的逐日遞增**。
   「甲,乙,丙」這種模板行為完全不變，不需要改任何既有資料
3. 下一輪照樣 `+7` 天。起日星期不變，所有日期整組平移，續辦邏輯不用動

### 起日的星期與第一個選項不一致時

以起日為錨點往後推。例如起日是星期日、第一個選項是「星期二」，
那「星期二」就是起日之後的那個星期二（+2 天），不是起日當天。

這是刻意的：起日的語意是「這一輪從哪一天開始算」，不是「第一個選項是哪一天」。

### `endDateOf()` 的簽章改變

原本是 `endDateOf(startDate, count)` = 起日 + 選項數 - 1。
同一天有早中晚三段時，選項數會比實際天數多，11 個選項會算出 8/28（錯，應為 8/24）。

改成 `endDateOf(bases, startDate)`，取所有選項算出來的日期裡最大的那一個。

### 既有的排程投票要能自動更正

`publishPending()` 原本只算截止時間就發出去，選項標籤是上一輪結算當下寫死的。
不處理的話，現在躺在 `data/polls/` 裡的 pending 下週還是會把錯的日期發出來，
等於這個 bug 修了沒有效果。

所以在 `publishPending()` 發布前依 `base` + `dateStart` 重算一次標籤。
標籤是衍生資料，重算冪等，不會有副作用。

影響範圍：

| 狀態 | 結果 |
|---|---|
| pending | 下次發布時自動更正，使用者不必做任何事 |
| open | 標籤已寫進 Discord 訊息，不回頭改，等結算後下一輪才正確 |
| archive | 歷史紀錄，不動 |

## 未涵蓋（另開單元）

使用者同時提出「`/poll_admin` 要能直接改投票選項」，2026-08-27 決定**暫緩**，
不在 U08 範圍內。設計草案（尚未定案）：

- 獨立一顆「編輯選項」按鈕，Modal 只放一格 Paragraph，一行一個選項
- 行數相同 → 逐行覆寫，`key` 不動，票全保留
- 行數變多 → 末尾附加新選項（新 `key`），舊票不受影響
- 行數變少 → 只有被刪掉的選項一張票都沒有時才允許
- 有起日的投票，Modal 顯示不含日期的 `base`，送出後自動重新套日期

## 驗收

### 單元測試（測試 jail）

```
npx vitest run tests/pollTemplate.test.js --no-file-parallelism --reporter=verbose
```

### 實機（測試 jail）

1. `/poll_admin` →「📋 模板管理」→ 選 MapleStory
   　「選項（套用後）」欄應顯示週末三段為同一天，「日期」欄的迄日應為起日 + 6 天
2. `/poll template:MapleStory title:測試` 發起一場
   　投票訊息上「星期六早上／下午／晚上」三個選項的日期應相同
3. 用不含星期的模板（或直接 `options:甲,乙,丙 date_start:2026-08-18`）發起
   　應維持逐日遞增 8/18、8/19、8/20
4. 既有的 pending 投票：`/poll_admin` 選那場 → 立即發布
   　發出來的選項日期應已更正
